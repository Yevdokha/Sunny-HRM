# v17.6.3 — виправлення матриці прав

## Що виправлено

- «Видача прав» тепер працює як додатковий шар: базові права ролі не забираються, індивідуальні права можуть лише розширювати доступ.
- Групове право «HR та аналітика — весь розділ» більше не перекриває вищі права окремого підрозділу. Застосовується максимальний із двох рівнів.
- Явно видане право `onboarding: edit/full` тепер реально делегує роботу з реєстром онбордингів/офбордингів, навіть якщо користувач не має ролі керівника/HR.
- Права на перегляд/відновлення видалених онбордингів та керування сервісами більше не блокуються назвою ролі — рішення приймається за матрицею прав.
- Право «Активація акаунтів» більше не блокується назвою ролі — якщо право видано, дія доступна.
- При зміні ролі базові права нової ролі застосовуються автоматично, а раніше окремо видані додаткові права зберігаються.
- Редагування ролі в профілі також контролюється окремим правом `role_edit`.
- Особисті документи та корпоративний GUID лишаються захищеними за погодженою бізнес-логікою й не делегуються звичайному співробітнику через матрицю.

## Модель доступу

Ефективний доступ = базове право ролі + окремо видане право, береться вищий рівень.

Рівні: `none < view < edit < full`.
