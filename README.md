# Sunny Ukraine — HRM (повний стек в одному Docker-наборі)

Бойова версія HRM: **PostgreSQL + Node.js (Fastify) + Caddy(HTTPS) + погоджений інтерфейс**,
усе в **Docker Compose**. Розгортання на **Hetzner**, за **VPN**.

## Швидкий старт
```bash
cp .env.example .env && nano .env      # паролі, домен, Google, SMTP
docker compose up -d --build           # БД + бекенд + Caddy; міграції застосуються самі
docker compose ps
```
Портал: `https://<ваш домен>`. Повна покрокова інструкція розгортання та **інформаційної
безпеки** — у **`DEPLOY_AND_SECURITY.md`**. Опис API — у **`API.md`**.

## Що всередині
```
docker-compose.yml        весь стек (db + backend + caddy)
.env.example              конфігурація
db/init/00_app_role.sh    НЕсуперюзерна роль застосунку (щоб діяв RLS)
caddy/Caddyfile           HTTPS
frontend/index.html       погоджений інтерфейс
backend/
  Dockerfile, package.json
  migrations/001_init.sql  схема бази (нові зміни → 002_*.sql)
  src/                     сервер, авторизація, маршрути API
DEPLOY_AND_SECURITY.md    єдина інструкція для адміна
API.md                    відкриті endpoint-и
```

## Ключове, що вже закладено
- **Незнищенність даних** — volume `pgdata`, окремо від коду; оновлення коду не стирає дані.
- **Активація акаунтів** — «Запрошено» → лист → пароль/Google → «Активовано»; HR бачить статус.
- **Індивідуальний залишок відпустки** — поле `vacation_days`; після фінального погодження дні віднімаються.
- **Авторизація** — пошта/пароль (будь-яка коректна адреса, самостійна реєстрація) + опційний вхід «Продовжити з Google» + «Забули пароль?» + автоблокування.
- **Приватність на рівні бази (RLS)** — бекенд ходить під роллю без прав суперюзера.
- **Відкриті API** — задокументовані endpoint-и під майбутні інтеграції (BAS).
- **Журнали** — спроби входу (без IP/пристрою в інтерфейсі) + журнал дій.
- **ШІ (опційно, безкоштовно)** — чат-помічник з навігації по системі та ШІ-оцінка резюме кандидатів відносно вакансії; вмикається змінною `GEMINI_API_KEY` у `.env` (безкоштовний рівень Google AI Studio, без картки) або `ANTHROPIC_API_KEY` як альтернатива; без ключа просто неактивні.

## ⚠️ Головне перед бойовим запуском
Погоджений `frontend/index.html` — це затверджений ІНТЕРФЕЙС-прототип (дані поки в памʼяті браузера).
Останній крок інтеграції — перенаправити його виклики на `/api/...` цього бекенду. Це окрема робота
розробника; Клод може видати «підключену» версію фронтенду окремо. Решта — база, логіка, безпека,
розгортання — у цьому наборі. Пройдіться по мітках **DEV-REVIEW** (див. `DEPLOY_AND_SECURITY.md`, розділ 8).

## Версія 14 — передсерверна збірка

Для локального тесту використовуйте `docker-compose.local.yml`. Для staging/production — `docker-compose.yml` разом із `.env.staging.example` або `.env.production.example`.

У staging і production обов’язково: `DEMO_SEED=false`. Першого адміністратора створюйте командою `npm run bootstrap-admin`, а не SQL seed.
